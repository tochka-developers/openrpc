# OpenRpc (Laravel/Lumen)

# Описание
Пакет для автоматической генерации документации JsonRpc-сервера по стандарту OpenRpc (https://spec.open-rpc.org/).
Совместим с пакетом `tochka-developers/jsonrpc`>=v5.0

# Установка
Установка через composer:
```shell
composer require tochka-developers/openrpc
```
### Laravel
Для Laravel есть возможность опубликовать конфигурацию для всех пакетов:
```shell
php artisan vendor:publish
```

Для того, чтобы опубликовать только конфигурацию данного пакета, можно воспользоваться опцией tag
```shell
php artisan vendor:publish --tag="openrpc-config"
```

# Настройка маршрута

```php
Route::get('/api/v1/public/openrpc', function () {
    $openRpc = new Tochka\OpenRpc\OpenRpc(
        OpenRpcConfig::makeFromConfigFile('default'),
        new Router(ServerConfig::makeFromConfigFile('default'))
    );

    return response($openRpc->handle())->header('Content-Type', 'application/json');
});
```

# Кеширование
OpenRpc может кешировать схему с описанием JsonRpc, чтобы не собирать ее каждый раз при вызове endpoint.
Для создания кеша используйте команду artisan:
```shell
php artisan openrpc:cache {server?}
```
После выполнения этой команды будет выполнена сборка схемы и сохранена в файл кеша. При каждом следующем обращении к 
OpenRpc будет использован именно этот файл, повторной пересборки происходить не будет. 
Если указать имя сервера, то будет закеширован указанный сервер, иначе будут закешированы все сервера из конфигурации.

Если файла с кешем нет - схема каждый раз будет собираться заново.

Чтобы очистить кеш - используйте команду artisan:
```shell
php artisan openrpc:clear {server?}
```
Рекомендуется запускать команду кеширования сразу после деплоя перед запуском приложения.

## Расширенное описание
Во многих объектах спецификации OpenRpc есть поле description, которое позволяет использовать MarkDown разметку.
Для более удобной организации есть возможность выносить эти описания в отдельные файлы с расширением .md, и затем в
описании ссылаться на них:
```php
'description' => '$views/docs/description.md'
```
В данном случае вместо указанного текста в поле подставится содержимое файла `resources/views/docs/description.md`.
Будьте внимательны! Документы должны находиться в папке resources, так как путь к файлу строится относительно этой 
директории.

## Основная информация
Вся основная информация о вашем приложении заполняется в конфигурации `openrpc.php`. В дефолтной конфигурации
описаны все поля, а также приведены примеры

## Информация о серверах (ендпойнты)
Ваше приложение может иметь несколько точек входа с разным списком методов. Все возможные конфигурации точек входа
JsonRpc-сервера описываются в конфигурации `jsonrpc.php`. Для корректного вывода информации о точках входа в OpenRpc
необходимо добавить еще несколько полей в конфигурацию каждого сервера JsonRpc:

```php
/** Адрес endpoint для текущего сервера */
'endpoint' => '/api/v1/public/jsonrpc',
/** Базовая информация о сервере/точки входа */
'summary' => 'Основная точка входа',
/** Расширенное описание сервера/точки входа */
'description' => 'Основная точка входа',
```

## Информация о методах
OpenRpc собирает информацию о доступных методах, получая информацию о 
[маршрутах из JsonRpc-сервера](https://github.com/tochka-developers/jsonrpc#%D0%BC%D0%B0%D1%80%D1%88%D1%80%D1%83%D1%82%D0%B8%D0%B7%D0%B0%D1%86%D0%B8%D1%8F-%D1%80%D0%BE%D1%83%D1%82%D0%B8%D0%BD%D0%B3).

Вы можете уточнять тип вложенных в массив элементов также с помощью тегов `@param` и `@return`:
```php
/**
 * @param array<int, MyType> $foo Описание параметра FOO
 * @param string[] $bar Описание параметра BAR
 * @return Result[]
 */
public function myMethod(array $foo, array $bar): array
{
    // ...
}
```
Если в качестве типа указан какой-либо класс - OpenRpc попытается описать внутреннюю структуру класса.

По умолчанию выбираются все публичные поля класса.

В качестве типа аргумента всегда выбирается тип поля. Поле считается обязательным, если у него нет дефолтного
значения или атрибута `Optional`.

Если в качестве типа поля указан `array` - вы можете уточнить тип элементов массива с помощью phpDoc в атрибуте `@var`:
```php
class TestDTO
{
    /** @var array<int> */
    public array $field;
    
    /** @var MyObject[] */
    public array $objects;
}
```

Если в качестве типа указан экземпляр `Illuminate\Database\Eloquent\Model` - OpenRpc получит все возможные поля из phpDoc
(как указано выше), а затем попытается отфильтровать их в соответствии с правилами, указанными в hidden и visible
(https://laravel.com/docs/8.x/eloquent-serialization#hiding-attributes-from-json)

### Вложенные объекты
OpenRpc описывает публичные поля вложенных объектов, в том числе поля, объявленные в конструкторе.
При чтении `@var` учитываются пространство имён и импорты класса, в котором объявлено поле.
Первая строка phpDoc используется как заголовок, остальной текст - как описание поля.

По умолчанию описание объекта добавляется в схему в месте его использования. Для того чтобы переиспользовать
описание одного класса в нескольких местах, добавьте к нему атрибут `SchemaReference`:
```php
namespace App\Dto;

use Tochka\OpenRpc\Attributes\SchemaReference;

#[SchemaReference]
class MyObject
{
    /**
     * Value
     *
     * Описание поля value
     * @var string
     */
    public string $value;
}

class TestDTO
{
    /** @var MyObject|null */
    public ?MyObject $object = null;

    /** @var MyObject[] */
    public array $objects;
}
```
В данном случае описание `MyObject` будет добавлено в `components.schemas` с ключом `App.Dto.MyObject`.
В местах использования класса будет указана ссылка `$ref` на эту схему. Если поле допускает `null`,
это также будет отражено в его описании.

Атрибут действует только на класс, у которого он указан, и не наследуется автоматически.
Для вложенных классов атрибут нужно указывать отдельно. Если классы ссылаются друг на друга по кругу,
добавьте `SchemaReference` к классу, на котором замыкается ссылка. Без него генерация завершится исключением
с указанием цепочки классов и полей.

Если атрибут указан у класса параметров запроса (`RequestObject`), описания его параметров будут добавлены
в `components.contentDescriptors`. В списке параметров метода будут указаны ссылки на эти описания.
Каждое описание содержит имя, заголовок, подробное описание, признак обязательности и ссылку на схему поля.
Если подробного описания нет, оно не добавляется. Параметры `RequestObject` описываются как именованные
(`paramStructure: by-name`): сначала обязательные, затем необязательные, с сохранением порядка внутри каждой группы.

### Необязательные поля
Поле, которое допускает `null`, считается обязательным, если у него нет дефолтного значения.
Для того чтобы явно указать необязательное поле, используйте атрибут `Optional`:
```php
use Tochka\OpenRpc\Attributes\Optional;

class TestDTO
{
    #[Optional]
    public ?string $foo = null;

    public function __construct(
        #[Optional]
        public readonly ?int $bar,
    ) {
    }
}
```
В данном случае поля `foo` и `bar` можно не передавать. Если поле передано, его значение должно соответствовать
указанному типу: `string` для `foo` и `integer` для `bar`. Тип `null` и дефолтное значение `null` не добавляются
в схему, даже если они указаны в PHP. Другие дефолтные значения сохраняются.

Для `mixed` и полей без типа и уточняющего PHPDoc допустимы любые JSON-значения, включая `null`.
Атрибут исключает такие поля из обязательных, но не ограничивает их значения. Дефолтное значение `null`
по-прежнему не добавляется в схему; это не запрещает передавать `null`.

Атрибут работает также для полей вложенных объектов и ответов. Он меняет только документацию:
тип поля, его значение и обязательность аргумента конструктора в PHP остаются прежними.
Типы элементов массива и полей вложенного объекта не меняются.

Если после удаления `null` остаётся один вариант типа, он описывается без `anyOf`.
Если вариантов несколько - `anyOf` сохраняется. Поле с единственным типом `null` вызовет исключение.

### Примеры значений
Вы можете добавить примеры возможных значений поля с помощью атрибута `Examples`:
```php
use Tochka\OpenRpc\Attributes\Examples;

class TestDTO
{
    #[Examples(['foo', 'bar'])]
    public string $value;

    /** @var array<int, int> */
    #[Examples([[1, 2, 3]])]
    public array $values;
}
```
Атрибут принимает массив примеров. Если само значение является массивом - укажите его как элемент массива примеров,
как показано для поля `values`. Типы значений сохраняются.

Атрибут можно указывать также у полей, объявленных в конструкторе. Примеры относятся к самому полю
и не добавляются к описанию элементов массива или общей схеме вложенного класса.

### Информация об ответе
OpenRpc забирает информацию о формате ответа из типа, указанного в качестве результата метода. При этом тип может быть 
указан также в phpDoc этого метода. При этом все возможности OpenRpc, описанные в предыдущем пункте для запросов - будут
также работать и для описания формата ответа.
